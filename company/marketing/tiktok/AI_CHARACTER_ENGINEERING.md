対象: こんびにこ型（AI育成×音声漫才）動画をJavisで再現するための技術解読書
前提資料: `CONVENICO_STYLE_PLAYBOOK.md`

## 1. 解読: なぜあのAIは流暢で面白いのか

結論から言うと、**特殊な技術は使っていない**。3つの要素の掛け算である。

### 要素A: 流暢さは「音声モードの製品性能」

こんびにこが使っているのはChatGPTの音声会話モード（現行はGPT-Live系）。
speech-to-speechのリアルタイム対話なので、流暢さ・相槌・間の取り方は
**製品側が最初から持っている能力**。ここに秘密はない。誰でも同じ流暢さは出せる。

### 要素B: 面白さの8割は「人格プロンプト（＝育成）」

「AI育成」と呼んでいるものの正体は、**カスタム指示＋メモリ機能による人格の固定**。
ポイントは以下の設計原則に集約される。

1. **欠陥を与える** — 完璧なAIは面白くない。「アホ」「辛辣」「自尊心過剰」など
   **一点の欠陥・偏り**を人格の核にする。笑いは欠陥から生まれる。
2. **AIらしさを禁止する** — 「丁寧な説明」「箇条書き」「〜ですね、他に何か？」を
   明示的に禁止。これを消すだけで一気に"キャラ"になる。
3. **返答を2文以内に縛る** — テンポ＝面白さ。長い返答は禁止事項として明記する。
4. **関係性を定義する** — 「ユーザーは飲み友」「ユーザーを煽ってよい」など、
   AIと人間の**上下関係・距離感**を指定する。漫才のボケとツッコミの配役である。
5. **一貫性を守らせる** — 「設定を絶対に破らない」「AIであることを言い訳にしない」。
   キャラが崩れた瞬間に視聴者は冷める。

### 要素C: 残りの2割は「人間側の芸」

- 振り（無茶振り・逆質問・しりとり等）の設計は人間の台本。
- AIの回答はアドリブに任せ、**撮れ高が出るまで3〜5テイク回す**。
- 編集（ジェットカット・テロップ・オチで即終了）が笑いを完成させる。

> つまり「教育方法」の正体 = **人格プロンプト設計 × テイク回し × 編集**。
> モデルを学習させ直しているわけではない。

## 2. 人格プロンプト設計書（育成テンプレート完全版）

```
# 人格
あなたは「{キャラ名}」。{一言で言える欠陥/偏り（例: 自尊心が異常に高いギャル）}。

# 口調
- 一人称は「{一人称}」、語尾は「{語尾}」
- 敬語禁止。話し言葉のみ。箇条書き・記号・絵文字は禁止

# 返答ルール（絶対）
- 必ず2文以内で返す
- 質問に素直に答えない。まず{キャラの反応パターン（例: 一回冷笑する）}
- 知らないことは知ったかぶりする（間違っていてよい）

# 関係性
- 相手（{ユーザー名}）はあなたの{関係（例: 毎晩一緒に飲む相手）}
- 相手を{態度（例: 基本塩対応、3回に1回だけデレる）}

# 禁止事項
- AIらしい丁寧な説明・謝罪・「他に何かありますか？」
- 設定を破ること。「私はAIなので」という逃げ
- 長文。3文以上書いたら失敗とみなす
```

### 育成のイテレーション（ここが「教育」）

1. 上記プロンプトで10往復ほど雑談し、**面白かった返答・スベった返答を記録**
2. スベった原因をプロンプトに反映（例: 説明癖が出た→禁止事項に追加）
3. 面白かった言い回しは「口癖」として人格に昇格させる（**持ちギャグ化**）
4. これを毎収録後に繰り返す。人格プロンプトは資産なので
   `company/marketing/tiktok/characters/` にバージョン管理する

## 3. Javisでの実装方法（2ルート）

### ルートA: 最速再現（こんびにこと同じ構成）— 今週から動ける

- 収録: ChatGPT音声モードに上記人格プロンプトを仕込み、スマホ画面収録
- Javisの役割: **制作パイプラインの頭脳**
  - 企画出し（週次で10案生成）・振り台本の作成
  - 収録ログの分析（どの発言がウケたか）→ プロンプト改訂案の生成
  - 投稿文・ハッシュタグ・サムネテキストの量産
- メリット: 初期コストゼロ、即開始。デメリット: 差別化しにくい

### ルートB: Javis自身をキャラAI化（自前実装）— 差別化＆商品化の本命

「自分のAI（Javis）と漫才している」こと自体がコンテンツの独自性になり、
かつ**この構築ノウハウがそのまま販売商品になる**。

パイプライン構成:

```
マイク音声 → STT（文字起こし） → Claude（人格プロンプト） → TTS（キャラ音声） → スピーカー
                                        ↑
                     持ちギャグ・過去のやりとりのメモリファイル
```

- STT: Whisper系のリアルタイム文字起こし
- 頭脳: Claude API（下記コード）
- TTS: ElevenLabs / VOICEVOX 等でキャラ固有の声を作る（声もキャラ資産）

会話部分の最小実装（Python / Anthropic SDK）:

```python
from anthropic import Anthropic

client = Anthropic()
PERSONA = open("characters/aho_ai_v3.md").read()  # 上記の人格プロンプト

history = []

def javis_reply(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    with client.beta.messages.stream(
        model="claude-opus-5",
        max_tokens=300,               # 返答を短く保つ（テンポ優先の意図的な制限）
        system=PERSONA,
        output_config={"effort": "low"},  # 雑談は低effortで速度優先
        betas=["server-side-fallback-2026-07-01"],
        fallbacks="default",
        messages=history,
    ) as stream:
        msg = stream.get_final_message()
    history.append({"role": "assistant", "content": msg.content})
    return "".join(b.text for b in msg.content if b.type == "text")
```

実装メモ:
- モデルは `claude-opus-5`。雑談ボットは `effort: "low"` でレイテンシと
  コストを下げる（キャラの面白さはプロンプト側で決まる）
- `fallbacks: "default"` はセーフティによる拒否時の自動フォールバック
  （煽り・毒舌キャラは稀に引っかかるため保険として有効化している）
- 人格プロンプト（system）は固定してプロンプトキャッシュを効かせる。
  持ちギャグの追記は末尾に足す
- 「メモリ」= 会話ログから面白かったやりとりを抽出して人格ファイルに
  追記するだけの仕組みで十分。ここはJavisの日次バッチにする

### 推奨: A→Bの二段構え

1〜4週目はルートAで投稿を回してデータ（何がウケるか）を貯め、
並行してルートBを構築。Bが動いたら「自作AIと漫才してみた」自体をネタにする。

## 4. 面白さの品質チェックリスト（投稿前）

- [ ] AIの返答はすべて2文以内か
- [ ] AIらしい丁寧語・説明口調が混ざっていないか（1箇所でもあればNGテイク）
- [ ] 冒頭2秒でキャラの欠陥が伝わるか
- [ ] 人間側のツッコミが入っているか（AIだけ喋る動画は伸びない）
- [ ] オチの直後に動画が終わっているか
